# CLAUDE.md — контекст конвейера для ИИ-помощника

Это загрузчик. Ты работаешь с конвейером автомонтажа вертикальных роликов.

**До первого запуска прочитай:**

1. [`README.md`](README.md) — состав конвейера, порядок шагов, что чем пересобирается.
2. [`ЭКРАН.md`](ЭКРАН.md) — почему слой устроен так: правила экрана, шестнадцать
   проверок гейта, ловушка расшифровки. Без этого ты будешь «чинить» то, что
   работает правильно.
3. [`НАСТРОЙКА.md`](НАСТРОЙКА.md) — когда правишь `настройки.json` или `proekt.json`.
4. [`ОТБОР.md`](ОТБОР.md) — когда речь про выбор кусков.

---

## Кто перед тобой

**Скорее всего не программист.** Владелец канала, который снял себя на камеру и
хочет готовый ролик. Он читал `МАНУАЛ.md`, а не исходники.

Отсюда:

- Говори, что делаешь, обычными словами. Не «падает `preflight` на В8» — а
  «проверка нашла, что на 14-й секунде подпись не влезает в строку».
- Ошибку в консоли не пересказывай дословно — объясни, что она значит и что ты
  собираешься делать.
- Решения, которые меняют результат (какой кусок брать, оставить ли повтор),
  принимает он. Решения, которые меняют механизм, — тоже он, но их надо
  сформулировать за него.

## 🔑 Семь правил, без которых ты сломаешь монтаж

**1. Не пропускай две остановки.** Они не формальность.

- После `otbor.py` — покажи таблицу кандидатов и **дождись выбора**. Правка в
  таблице стоит минуту, та же правка после рендера — час.
- После `sborka.py` — **покажи человеку текст собранного ролика подряд** и
  дождись ответа. Гейт сверяет результат с планом и не видит того, что
  потерялось ДО плана: тихое слово, срезанное вместе с паузой, и повтор,
  который расшифровка вычистила на всплесках. Это ловится только чтением.

**2. Решения — в `proekt.json`, никогда в код.** Всё, что относится к
конкретному ролику (что убрать, что вернуть, как написать подпись, где сноска),
живёт в `proekt.json`. Скрипты общие для всех роликов. Правка кода ради одного
ролика ломает механизм для всех следующих — и заметно это станет не сразу.

**3. Не выключай и не ослабляй проверки.** Каждая из шестнадцати выросла из
дефекта, который однажды уже уехал в готовый ролик. Проверка кричит впустую —
значит она неверно написана, чини её. Не глуши. Исключение объявляется явно и с
обоснованием, которое печатается в отчёте.

**4. Чини механизм, а не место.** Нашёлся дефект — спроси себя, почему его не
поймала ни одна проверка, и поставь ворота. Поправить конкретный ролик — значит
встретить тот же дефект в следующем.

**5. Не выдумывай фактуру.** На экране стоит то, что прозвучало. Расшифровка
потеряла слово — послушай кусок подряд (`okno.py --окно 105-114`) и восстанови
по звуку. Подставить правдоподобное нельзя: это вранье в кадре, и поймать его
сможет только человек на просмотре.

**6. Расшифровка — не протокол.** Модель вычищает запинки, выписывает
повторённую фразу один раз (на времени ПЕРВОГО захода) и растягивает времена
слов. Границы кусков берутся из огибающей звука, а не из `words.json`. Разбор —
`ЭКРАН.md` §8. Не считай механизм сломанным, пока не проверил это.

**7. Гейт прогоняется дважды** — до рендера слоя (не рендерить брак) и после
(проверки, меряющие нарисованное, без слоя честно говорят, что замер не
проводился). Не сокращай до одного раза.

## Порядок работы

```bash
cd скрипты
python rech.py     --проект "N"     # расшифровка (самый долгий шаг, кэшируется)
python dubli.py    --проект "N"     # пересъёмки → чистая речь
python otbor.py    --проект "N"     # ← ОСТАНОВКА 1: таблица кандидатов
python rez.py      --проект "N" --кандидат 1
python kadr.py     --проект "N"     # замер лица, окно 9:16, крупности
python titry.py    --проект "N"     # субтитры и акценты
python sborka.py   --проект "N"     # ← ОСТАНОВКА 2: прочитать текст сборки
python proverki.py --проект "N"     # гейт до рендера
node ../слой/render_reel.mjs "../проекты/N/titry.json" "../проекты/N/выход/слой.mov"
python proverki.py --проект "N"     # гейт после рендера
python nalozhit.py --проект "N"     # композит
python kadry.py    --проект "N"     # лист контрольных кадров
python finaly.py   --проект "N" --серия "…"   # единственная дверь в финалы
```

Ролик снят целиком — `otbor.py` пропускается, границы задаются ключом
`--окна "01:2.1-9.2/целиком, 01:81-152"`.

Спорное место слушается отдельно: `python okno.py --проект "N" --окно 105-114`.
Этот скрипт ничего не пишет в проект — он для чтения.

## Что делать с правками человека

Он говорит живыми словами — переводи сам:

| Он сказал | Куда это идёт |
|---|---|
| «этот кусок убери» | `правки_отбора.<файл>.убрать`, время начала всплеска из `РЕЧЬ.md` |
| «эту фразу верни» | `правки_отбора.<файл>.вернуть` |
| «здесь он расслышал неверно» | `правки_текста`: слева — как в `РЕЧЬ.md`, справа — как писать |
| «поставь дату опыта» | `сноски`: якорь в речи → текст на экран |
| «запикай это слово» | `запикивания` |
| «заголовок другой» | `заголовок.строка1` / `строка2` |
| «графика однообразная» | это про механизм, а не про ролик — смотри В11 и `ЭКРАН.md` §1.1 |

⚠️ Записывая причину правки в `почему_правки`, пиши её так, чтобы через месяц
было понятно без разговора. Это единственное место, где остаётся «почему».

⚠️ Если механизм сам выбрал лишний дубль, недостаточно убрать его из `вернуть`
— он вернётся по автоматическому решению. Назови его явно в `убрать`.

## Границы

- Русская речь: язык меняется в настройках, но словари отбора и знаков написаны
  под русский.
- Одно лицо в кадре.
- Говорящая голова: b-roll, музыки, склеек по движению здесь нет.
- Набор сцен инфографики (`слой/src/Sceny.tsx`) пуст намеренно — сцена рисует
  конкретный опыт конкретного ролика. Проверка В16 по умолчанию выключена.

Список того, что механизм НЕ ловит, печатается в `ГЕЙТ.md` на каждом прогоне.
Он обязан сокращаться, а не выглядеть пустым: нашёл дефект, которого там нет, —
допиши.
