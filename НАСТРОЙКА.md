# НАСТРОЙКА.md

Две разные вещи настраиваются в двух разных местах, и путать их не стоит:

- **`настройки.json`** в корне — всё, что относится к **вам и вашей машине**:
  канал, кодировщик, громкость, модель расшифровки. Один раз на репозиторий.
- **`проекты/<имя>/proekt.json`** — всё, что относится к **одному ролику**: где
  сырьё, какие файлы, ручные правки. Свой на каждый ролик.

Кода не трогают ни там, ни там.

---

## Часть 1. `настройки.json`

Скопируйте образец и правьте копию:

```bash
cp настройки.пример.json настройки.json
```

Своей копии нет — конвейер работает по образцу. Так сделано нарочно: свежий
клон обязан запускаться сразу, а не после заполнения анкеты.

> `настройки.json` лежит в `.gitignore`. Ваши пути и настройки машины не уедут
> в репозиторий, даже если вы форкнете его и будете коммитить.

### `канал`

```json
"канал": {
  "название": "Ваш канал",
  "якорь_в_речи": "ваш\\s+канал|вашканал"
}
```

Когда вы произносите название канала вслух, на экране появляется плашка с его
**написанием**. Сказали «залетай ко мне на Ваш Канал» — зритель видит, как это
пишется.

- **`название`** — что писать на плашке. Пустая строка — плашки не будет.
- **`якорь_в_речи`** — регулярное выражение, по которому механизм узнаёт
  название в расшифровке. Простого сравнения недостаточно: на слух название
  распадается («мой канал» → «мой-канал», «Мой Канал»), и точное
  совпадение промахнётся на первом же ролике. Пишите `\\s+` вместо пробела и
  перечисляйте варианты через `|`.

Логотип рядом с названием — **файл** `слой/public/бренд/знак.png` (прозрачный
PNG). Файла нет — плашка покажет одно название, и это не поломка. Логотип не
рисуется кодом: точность знака и есть знак, а «похожий» контур читается как
подделка (`ЭКРАН.md` §3).

### `видео`

```json
"видео": {"кодировщик": "авто", "preset": "medium"}
```

- **`кодировщик`** — `авто` перебирает `h264_qsv` → `h264_nvenc` →
  `h264_videotoolbox` → `libx264` и берёт первый доступный, объявляя выбор
  вслух. Можно задать точно; если названного нет на машине, конвейер скажет об
  этом и возьмёт `libx264`, а не упадёт.
- **`preset`** — только для `libx264`: `ultrafast` … `veryslow`. Быстрее —
  крупнее файл. `medium` подходит почти всегда.

### `звук`

```json
"звук": {"громкость_lufs": -16.0, "пик_dbtp": -1.5}
```

Цель нормализации. Площадки приводят звук примерно к −14 LUFS: если отдать им
−23, они поднимут уровень **вместе с шумом**. −16 с запасом по пику −1,5 dBTP
— рабочая цель. Проверка В9 сверяет результат с этим числом, допуск 1,5 LUFS.

### `расшифровка`

```json
"расшифровка": {"модель": "large-v3-turbo", "устройство": "cpu", "язык": "ru", "потоков": 8}
```

- **`модель`** — `large-v3-turbo` точнее всего; `medium` и `small` быстрее и
  легче, но хуже слышат. Качество расшифровки — это не только субтитры: на ней
  же работают отбор кусков, детектор пересъёмок и вся разметка.
- **`устройство`** — `cpu` или `cuda`. На `cuda` точность считается `float16`,
  на `cpu` — `int8` (иначе час сырья уходит за ночь).
- **`язык`** — код языка. Механизм многоязычный, но словари отбора и знаков
  написаны под русский (`README.md`, «Границы честно»).
- **`потоков`** — сколько ядер отдать расшифровке на CPU.

### `выход`

```json
"выход": {"финалы": "финалы"}
```

Папка, куда `finaly.py` кладёт принятые ролики. Относительный путь считается от
корня репозитория, абсолютный берётся как есть — финалы удобно держать рядом с
сырьём, на другом диске.

### `гейт`

```json
"гейт": {"требовать_инфографику": false}
```

Включает проверку **В16**. По умолчанию выключена: набор сцен
`слой/src/Sceny.tsx` пуст, и с включённой В16 ни один ролик не станет финалом.
Включайте, когда напишете свои сцены (`ЭКРАН.md` §6).

## Часть 2. `proekt.json` — один ролик

Минимум, с которого можно начать:

```json
{
  "имя": "МОЙ РОЛИК",
  "сырьё": "D:\\Съёмки\\2026-03-14",
  "формат": "рилз 1080x1920, 30 fps"
}
```

| Ключ | Что делает |
|---|---|
| `имя` | как ролик называется в отчётах |
| `сырьё` | **папка** с исходными файлами. Относительный путь — от корня репозитория; абсолютный тоже годится, и обычно так и делают: сырьё весит десятки гигабайт и в репозитории ему не место |
| `файлы` | какие файлы брать и **в каком порядке**, если в папке лежит несколько роликов сразу. Без этого ключа берутся все по алфавиту — а второй файл вполне может быть продолжением первого, и тогда алфавит врёт |
| `заголовок` | две строки титра открытия. Не задан — механизм предложит свои варианты в `СЛОЙ.md` |
| `правки_отбора` | ручные правки: что выбросить и что вернуть, по времени в сырье |
| `почему_правки` | зачем вы это сделали. Через месяц спасает вас же |
| `правки_текста` | пары «что услышала машина» → «что писать на экране» |
| `сноски` | плашки-уточнения: якорь в речи → ваш текст на экран |
| `запикивания` | цензура: слово в речи → тон в звуке и звёздочки в субтитре |
| `инфографика` | раскадровка: имя сцены из `Sceny.tsx` и её данные |

### Ручные правки отбора

```json
"правки_отбора": {
  "01": {
    "убрать": [18.96, 73.56, 113.08],
    "вернуть": [67.34, 376.78]
  }
},
"почему_правки": {
  "18.96": "«Ой, ну» — междометие между репликами",
  "73.56": "первый подход к именам, взят целый заход на 117.54"
}
```

Числа — **время начала всплеска в сырье**, как оно напечатано в `РЕЧЬ.md`.

⚠️ Если механизм сам выбрал лишний дубль, недостаточно убрать его из `вернуть`
— он снова попадёт в монтаж по автоматическому решению. Такой кусок нужно явно
назвать в `убрать`.

### Правки текста

```json
"правки_текста": [
  ["знаете, что такое беглость обработки, у нейросетей 2008",
   "Знаете, что такое беглость обработки у нейросетей?"]
]
```

Слева — то, что услышала машина (копируйте из `РЕЧЬ.md` как есть). Справа — то,
что увидит зритель. Заодно чинятся пунктуация и оборванные концы фраз.

### Цензура

```json
"запикивания": [{
  "на": "слово",
  "субтитр": "с***о",
  "середина": [0.22, 0.78],
  "частота": 1000,
  "уровень": 0.36
}]
```

Один якорь на звук и на субтитр сразу: отдельный ручной таймкод для писка и
отдельная правка подписи разъехались бы при первой же новой сборке. Начало и
конец слова остаются слышны, чистый тон **заменяет** середину, а не маскирует
её. Якорь обязан встретиться ровно один раз: ноль или два совпадения — жёсткая
ошибка до рендера.

## Часть 3. Как поменять вид

**Цвета** — `слой/src/tokens.ts`. Меняйте `blue` и два его оттенка на свой
акцентный цвет. Новых цветов не добавляйте: как только акцентов больше одного,
акцент перестаёт работать — зритель видит пестроту, а не выделение.

**Шрифты** — `слой/src/Reel.tsx` и `слой/src/Subtitles.tsx`, верхние строки:

```ts
import {loadFont as loadSerif} from '@remotion/google-fonts/Prata';
```

Замените на любой шрифт из Google Fonts — **проверив, что у него есть
кириллица** (в `subsets` указан `cyrillic`). Вес, которого нет в загрузке,
браузер молча подменит своим: это не ошибка рендера, а просто другой шрифт на
экране, и заметить такое можно только глазами.

**Геометрия кадра** — `слой/src/zones.ts`. Поля под интерфейс площадки
(`VERT`). Меняйте, если площадка перерисует свой интерфейс.

**Гнёзда субтитров** — `слой/src/Subtitles.tsx`, массив `GNEZDA`. Их восемь с
лишним намеренно: лицо занимает верхнюю половину кадра, и при четырёх гнёздах
работают фактически два (`ЭКРАН.md` §1.1).

**Словарь знаков** — `слой/src/Znachki.tsx` (сами SVG) и `titry.py` (словарь
«слово в речи → предмет»). Свои знаки берите готовыми файлами из открытого
набора, а не рисуйте примитивами.
